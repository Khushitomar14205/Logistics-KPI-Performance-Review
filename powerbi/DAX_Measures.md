## 2. Power Query preparation (do this before writing DAX)

1. **Fact_Shipment** — set types: `shipment_date` → Date; `promised_ts_utc` / `actual_ts_utc` → Date/Time
   (strip the UTC offset in Power Query: the stored values are already UTC, so use
   `DateTimeZone.ToLocal`/`DateTimeZone.RemoveZone` consistently — do **not** re-interpret them as IST);
   `shipment_cost_inr`, `late_hours`, `dwell_origin_h`, `dwell_dest_h`, `dwell_avg_h` → Decimal Number;
   `on_time`, `cost_valid`, `dwell_origin_valid`, `dwell_dest_valid` → **True/False (logical)** — the CSV stores
   them as text (`True`/`False`/blank), and every measure below depends on them being logical, not text.
   Rename the table to `Fact_Shipment`. Add a calculated column for the prior-period comparison:
   `Half = IF ( MONTH ( Fact_Shipment[shipment_date] ) <= 6, "H1 2025", "H2 2025" )`.
2. **Dim_Route** — append `dim_route_unknown_member.csv` (one row, `route_id = UNKNOWN`).
   **Dim_Vehicle** — append one row: `vehicle_id = UNKNOWN`, `vehicle_type = Unknown`, other columns blank.
   **Dim_Category** — append one row: `category = Unknown`, `base_cost_inr` blank.
   Without these appends, UNKNOWN/Unknown shipments drop out of visuals that slice by route, vehicle or category.
3. **Dim_Date** — `date` → Date type. In Model view, right-click `Dim_Date` → **Mark as date table**,
   using `Dim_Date[date]`. This is required for the `PREVIOUSMONTH` time-intelligence measure in §4.
4. **Fact_Scan_Event** (only if loaded) — `scan_ts_utc` → Date/Time; `scan_sequence` → Whole Number.

## 3. Star schema — relationships (Model view)

All relationships are **single-direction, many-to-one** (`*` → `1`) from fact to dimension, so a dimension
filter can never fan out shipment rows. Cross-filter direction stays single (dimension filters fact).

| From (many) | To (one) | Join keys | Active? |
|---|---|---|---|
| `Fact_Shipment[destination_hub]` | `Dim_Hub[hub_id]` | hub id | **Yes** — the active hub relationship; hub slicers/visuals use the **destination** hub by default |
| `Fact_Shipment[origin_hub]` | `Dim_Hub[hub_id]` | hub id | **No (inactive)** — same dimension, second role. Use `USERELATIONSHIP` (see `OTD % (Origin Hub)` in §4) whenever a visual must slice by origin hub |
| `Fact_Shipment[route_id]` | `Dim_Route[route_id]` | route id | Yes |
| `Fact_Shipment[vehicle_id]` | `Dim_Vehicle[vehicle_id]` | vehicle id | Yes |
| `Fact_Shipment[category]` | `Dim_Category[category]` | category | Yes |
| `Fact_Shipment[warehouse_id]` | `Dim_Warehouse[warehouse_id]` | warehouse id | Yes |
| `Fact_Shipment[shipment_date]` | `Dim_Date[date]` | date | Yes |
| `Fact_Scan_Event[shipment_id]` | `Fact_Shipment[shipment_id]` | shipment id | Yes (only if the scan fact is loaded) |
| `Fact_Scan_Event[hub_id]` | `Dim_Hub[hub_id]` | hub id | Yes (only if the scan fact is loaded) |
| `Fact_Scan_Event[warehouse_id]` | `Dim_Warehouse[warehouse_id]` | warehouse id | Yes (only if the scan fact is loaded) |
| `Dim_Warehouse[hub_id]` | `Dim_Hub[hub_id]` | hub id | Yes (dimension-to-dimension; lets a hub slicer filter warehouses) |

Note: `Dim_Route[origin_hub]` / `Dim_Route[destination_hub]` and `Dim_Vehicle[home_hub]` are descriptive
attributes only — do **not** create relationships on them, or the model will have ambiguous paths to `Dim_Hub`.

## 4. Measures

Create all measures in a dedicated measure table (Model → New table: `KPI Measures = {0}`, then hide its column)
or directly on `Fact_Shipment`. Format each measure as shown; the formats assume the full trusted table — see the
sample warning in §1 for the values the sample CSV produces instead.

### 4.1 Volume

```dax
Total Shipments =
COUNTROWS ( Fact_Shipment )
```

```dax
OTD Eligible Shipments =
-- Eligible = status Delivered/Delayed AND promised & actual timestamps both valid.
-- Cancelled / Returned / In-Transit shipments never completed delivery and are excluded.
CALCULATE (
    COUNTROWS ( Fact_Shipment ),
    Fact_Shipment[status] IN { "Delivered", "Delayed" },
    NOT ( ISBLANK ( Fact_Shipment[on_time] ) )
)
```

```dax
On-Time Deliveries =
CALCULATE (
    COUNTROWS ( Fact_Shipment ),
    Fact_Shipment[status] IN { "Delivered", "Delayed" },
    Fact_Shipment[on_time] = TRUE ()
)
```

```dax
Late Deliveries =
-- Eligible shipments with actual > promised. Equivalent to [OTD Eligible Shipments] - [On-Time Deliveries].
CALCULATE (
    COUNTROWS ( Fact_Shipment ),
    Fact_Shipment[status] IN { "Delivered", "Delayed" },
    Fact_Shipment[on_time] = FALSE ()
)
```

### 4.2 On-time delivery %

```dax
OTD % =
DIVIDE ( [On-Time Deliveries], [OTD Eligible Shipments] )
-- Format: Percentage, 2 decimals. Full-table value: 76.48%.
```

```dax
OTD % (Origin Hub) =
-- Same OTD definition, but slicing by ORIGIN hub through the inactive relationship.
CALCULATE (
    [OTD %],
    USERELATIONSHIP ( Fact_Shipment[origin_hub], Dim_Hub[hub_id] )
)
```

```dax
OTD % MoM Change (pp) =
-- Month-over-month change in percentage points. Needs Dim_Date marked as a date table (§2).
VAR CurrentOTD = [OTD %]
VAR PriorOTD =
    CALCULATE ( [OTD %], PREVIOUSMONTH ( Dim_Date[date] ) )
RETURN
    IF ( NOT ISBLANK ( PriorOTD ), ( CurrentOTD - PriorOTD ) * 100 )
-- Format: Decimal Number, 2 decimals, with a +/- sign. Jan 2025 is blank (no prior month).
-- Observed range in 2025: -1.04 pp (Apr) to +1.32 pp (May); the monthly OTD range is 75.72%–77.04%.
```

```dax
OTD % H1 2025 =
CALCULATE ( [OTD %], Fact_Shipment[Half] = "H1 2025" )
-- Full-table value: 76.49%.
```

```dax
OTD % H2 2025 =
CALCULATE ( [OTD %], Fact_Shipment[Half] = "H2 2025" )
-- Full-table value: 76.47%.
```

```dax
OTD % Half-Year Change (pp) =
-- Prior-period comparison (H1 vs H2 2025). This is NOT year-over-year: data covers 2025 only.
( [OTD % H2 2025] - [OTD % H1 2025] ) * 100
-- Full-table value: -0.02 pp (76.47% - 76.49%). Label it "H2 vs H1 2025", never "YoY".
```

### 4.3 Cost per shipment

```dax
Total Valid Cost (INR) =
-- Only costs flagged valid (positive and recorded). Negative / zero / missing costs are excluded,
-- never overwritten: the shipment row stays in the table, only its cost leaves the denominator.
CALCULATE (
    SUM ( Fact_Shipment[shipment_cost_inr] ),
    Fact_Shipment[cost_valid] = TRUE ()
)
-- Format: Currency (₹, en-IN), 0 decimals. Full-table value: ₹1,20,40,74,834.
```

```dax
Valid Cost Shipments =
CALCULATE (
    COUNTROWS ( Fact_Shipment ),
    Fact_Shipment[cost_valid] = TRUE ()
)
-- Full-table value: 293,485 of 300,000 shipments.
```

```dax
Cost per Shipment (INR) =
DIVIDE ( [Total Valid Cost (INR)], [Valid Cost Shipments] )
-- Format: Currency (₹, en-IN), 2 decimals. Full-table value: ₹4,102.68.
```

```dax
Cost per Shipment MoM Change (%) =
VAR CurrentCost = [Cost per Shipment (INR)]
VAR PriorCost =
    CALCULATE ( [Cost per Shipment (INR)], PREVIOUSMONTH ( Dim_Date[date] ) )
RETURN
    IF ( NOT ISBLANK ( PriorCost ), DIVIDE ( CurrentCost - PriorCost, PriorCost ) )
-- Format: Percentage, 2 decimals.
```

### 4.4 Dwell time

```dax
Avg Destination Dwell (h) =
-- Mean of (Delivered - Arrival) over valid, non-negative pairs only.
CALCULATE (
    AVERAGE ( Fact_Shipment[dwell_dest_h] ),
    Fact_Shipment[dwell_dest_valid] = TRUE (),
    NOT ( ISBLANK ( Fact_Shipment[dwell_dest_h] ) )
)
-- Format: Decimal Number, 2 decimals. Full-table value: 15.49 h.
```

```dax
Avg Origin Dwell (h) =
-- Mean of (Departure - Loading) over valid, non-negative pairs only.
CALCULATE (
    AVERAGE ( Fact_Shipment[dwell_origin_h] ),
    Fact_Shipment[dwell_origin_valid] = TRUE (),
    NOT ( ISBLANK ( Fact_Shipment[dwell_origin_h] ) )
)
-- Format: Decimal Number, 2 decimals. Full-table value: 2.50 h.
```

```dax
Avg Combined Dwell (h) =
-- Row-wise mean of origin and destination dwell, averaged over shipments.
AVERAGE ( Fact_Shipment[dwell_avg_h] )
-- Format: Decimal Number, 2 decimals. Full-table value: 8.90 h.
```

```dax
Avg Destination Dwell MoM Change (%) =
VAR CurrentDwell = [Avg Destination Dwell (h)]
VAR PriorDwell =
    CALCULATE ( [Avg Destination Dwell (h)], PREVIOUSMONTH ( Dim_Date[date] ) )

    IF ( NOT ISBLANK ( PriorDwell ), DIVIDE ( CurrentDwell - PriorDwell, PriorDwell ) )

```

## 5. Scorecard RAG status measures

Thresholds are **analyst-defined reporting conventions for this review** (defined in the notebook §11) — they are
not measured targets from the data, and they must be labelled as such on the dashboard:

- **OTD %:** Green ≥ 85% · Amber 75–85% · Red < 75%
- **Cost per shipment:** Green ≤ ₹4,000 · Amber ₹4,000–4,500 · Red > ₹4,500
- **Avg destination dwell:** Green ≤ 12 h · Amber 12–18 h · Red > 18 h

```dax
OTD RAG Status =
VAR OTDValue = [OTD %]
RETURN
    SWITCH (
        TRUE (),
        ISBLANK ( OTDValue ), "— No data",
        OTDValue >= 0.85, "● Green — on target (≥ 85%)",
        OTDValue >= 0.75, "● Amber — below target (75–85%)",
        "● Red — needs action (< 75%)"
    )
-- Full-table value: "● Amber — below target (75–85%)" (76.48%).
```

```dax
Cost RAG Status =
VAR CostValue = [Cost per Shipment (INR)]
RETURN
    SWITCH (
        TRUE (),
        ISBLANK ( CostValue ), "— No data",
        CostValue <= 4000, "● Green — at or below ₹4,000",
        CostValue <= 4500, "● Amber — ₹4,000–4,500",
        "● Red — needs action (> ₹4,500)"
    )
-- Full-table value: "● Amber ..." (₹4,102.68).
```

```dax
Dwell RAG Status =
VAR DwellValue = [Avg Destination Dwell (h)]
RETURN
    SWITCH (
        TRUE (),
        ISBLANK ( DwellValue ), "— No data",
        DwellValue <= 12, "● Green — at or below 12 h",
        DwellValue <= 18, "● Amber — 12–18 h",
        "● Red — needs action (> 18 h)"
    )
-- Full-table value: "● Amber ..." (15.49 h).
```

```dax
Network Scorecard Status =
-- One-line roll-up for the Executive Overview header. Counts how many of the three headline
-- KPIs are Green / Amber / Red under the thresholds above.
VAR OTDStatus =
    SWITCH ( TRUE (), [OTD %] >= 0.85, "Green", [OTD %] >= 0.75, "Amber", "Red" )
VAR CostStatus =
    SWITCH (
        TRUE (),
        [Cost per Shipment (INR)] <= 4000, "Green",
        [Cost per Shipment (INR)] <= 4500, "Amber",
        "Red"
    )
VAR DwellStatus =
    SWITCH (
        TRUE (),
        [Avg Destination Dwell (h)] <= 12, "Green",
        [Avg Destination Dwell (h)] <= 18, "Amber",
        "Red"
    )
VAR Greens =
    ( IF ( OTDStatus = "Green", 1, 0 ) + IF ( CostStatus = "Green", 1, 0 ) + IF ( DwellStatus = "Green", 1, 0 ) )
VAR Reds =
    ( IF ( OTDStatus = "Red", 1, 0 ) + IF ( CostStatus = "Red", 1, 0 ) + IF ( DwellStatus = "Red", 1, 0 ) )
RETURN
    SWITCH (
        TRUE (),
        Reds > 0, "● Red — " & Reds & " of 3 KPIs need action",
        Greens = 3, "● Green — all 3 KPIs on target",
        "● Amber — " & Greens & " of 3 KPIs on target, none Red"
    )
-- Full-table value: "● Amber — 0 of 3 KPIs on target, none Red"
-- (OTD Amber, Cost Amber, Dwell Amber — no KPI is Green or Red at network level).
```

Apply conditional formatting on the card/table visuals that show these text measures: font colour Green
(`#27AE60`) / Amber (`#E67E22`) / Red (`#C0392B`) by rules on the underlying numeric measure
(`[OTD %]`, `[Cost per Shipment (INR)]`, `[Avg Destination Dwell (h)]`), not on the text itself.

## 7. What is deliberately not in DAX

- **No YoY measure.** The data covers 2025 only; a YoY measure would divide by a blank prior year. Use
  `[OTD % Half-Year Change (pp)]` and `[OTD % MoM Change (pp)]` instead.
- **No dwell-to-rupees conversion.** No verified per-hour handling cost exists in the data, so no measure
  multiplies dwell hours by a rupee rate. Business-impact dwell savings stay in hours (4,295.8 h realistic case).
- **No imputation.** Missing costs/timestamps stay excluded via the `*_valid` flags and `ISBLANK` tests; no measure
  fills them with an average.
- **No business-impact measures.** The 9,706 late deliveries avoided / ₹31,13,833 saving / 4,295.8 dwell hours are
  modelled scenario outputs from `src/kpi_calculations.py` (bottom-quartile segments converging to the median),
  not row-level facts — show them as static text/values on the Executive Overview page, sourced from
  `outputs/kpi_reports/kpi_summary.json` (`business_impact.scenarios.realistic`), labelled "modelled estimate on
  synthetic data, not a forecast".
