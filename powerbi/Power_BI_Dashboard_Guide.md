# Power BI Dashboard Guide — Logistics KPI Performance Review

> ⚠️ **ALL DATA IS SYNTHETIC** (seed 42, generated by `src/generate_data.py`). Nothing in this dashboard describes
> a real company. The series covers **2025 only** — there is **no true year-over-year** comparison; H1 vs H2 2025
> is the prior-period comparison and must be labelled as such on every visual that uses it.
>
> ## Open the ready-made dashboard (recommended)
>
> A Power BI `.pbix` file **cannot be generated by code** — it is a proprietary binary that only Power BI Desktop
> can create. So this project ships the next best thing, already built and structurally validated
> (`powerbi/VALIDATION.md`, 519/519 checks pass), and one Refresh + Save As in Desktop turns it into a `.pbix`:
>
> **Option A — template (easiest).** `powerbi/Logistics_KPI_Performance_Review.pbit`
> 1. In Power BI Desktop: **File → Open** → the `.pbit` file.
> 2. When prompted, set the **`DataFolder`** parameter to the full path of the `powerbi/data` folder in this repo
>    (ending with a backslash, e.g. `C:\Users\you\Logistics-KPI-Performance-Review\powerbi\data\`).
>    The 16 CSVs in that folder are the import source — no other files are needed.
> 3. **Home → Refresh**, wait for the 300,000-row fact to load, then **File → Save As → `.pbix`**.
>    That saved file is the deliverable `.pbix`.
>
> **Option B — project folder.** `powerbi/Logistics_KPI_Performance_Review.pbip/` (open the `.pbip` file in
> Desktop). Same `DataFolder` prompt, same Refresh, same Save As. Use this if Desktop reports a mashup error
> opening the `.pbit` — the `.pbip` reads the M queries straight from `model.bim`, so it is the more robust path.
>
> **What you get:** 4 pages (Executive Overview, Hub & Warehouse Performance, Route & Shipment Analysis,
> Data Quality Monitoring), 54 visuals, 26 DAX measures from `powerbi/DAX_Measures.md`, slicers for month / hub /
> category on every page, RAG status text measures on the KPI cards (OTD Green ≥85% / Amber 75–85% / Red <75%;
> cost Green ≤₹4,000 / Amber ≤₹4,500 / Red >₹4,500; dwell Green ≤12h / Amber ≤18h / Red >18h).
> Headline numbers after refresh: OTD **76.48%**, cost **₹4,102.68**, dwell **15.49 h** (full 300,000-row fact).
>
> **Two 30-second manual steps after opening:**
> - **Top N filters** are not encoded in the file (route charts are sorted by the measure instead). In the
>   Filters pane, set Top N = 10 on the route OTD bar (worst routes) and Top N = 15 on the Pareto chart.
>   See §4 for the exact visuals.
> - **Mark `Dim_Date` as a date table** (right-click `Dim_Date` → Mark as date table) so `PREVIOUSMONTH`
>   behaves exactly as documented. The MoM measures compute regardless via the date relationship.
>
> **If you would rather build it yourself** (or check the generated files), the manual route is still
> documented below (§1 onwards) — the import-ready datasets, the full DAX set in `powerbi/DAX_Measures.md`,
> and the page-by-page build order. Budget roughly 60–90 minutes for a first manual build. The reference
> implementation of the same charts in matplotlib lives in `visualizations/`
> (`01_monthly_otd_trend.png` … `08_late_delivery_pareto.png`, built by `src/visualizations.py`)
> — use them to check that each Power BI visual tells the same story.

## 0. Before you start

- **Software:** Power BI Desktop (free, Windows). No Premium capacity or gateway is needed; all data is local files.
- **Files:** the repo at `logistics-kpi/` — for the ready-made dashboard you need `powerbi/Logistics_KPI_Performance_Review.pbit`
  (or the `.pbip` folder) plus `powerbi/data/` (16 CSVs, 69 MB). For a manual build you need `data/processed/`,
  `data/reference/`, `outputs/kpi_reports/kpi_summary.json` (headline numbers) and `powerbi/DAX_Measures.md` (measures).
- **Decide: sample or full table?** `Fact_Shipment` from the 10,000-row sample CSV builds fast and is enough to
  learn the layout, but its cards show **approximate** values (OTD 76.62%, cost ₹4,123.31, dwell 15.38 h).
  For the exact headline numbers (OTD **76.48%**, cost **₹4,102.68**, dwell **15.49 h**), import the full
  `trusted_analysis_table.parquet` (300,000 rows) instead — Get Data → Parquet. The measures and this guide are
  identical either way. Do not mix the two: load one or the other as `Fact_Shipment`. (The ready-made
  `.pbit`/`.pbip` already uses the full 300,000-row fact from `powerbi/data/Fact_Shipment.csv`.)
- **Conventions used in this guide:** `Measure names` are in `[square brackets]` and are defined in
  `DAX_Measures.md`; *Field names* are in *italics*; **RAG** = Red/Amber/Green status (thresholds in
  `DAX_Measures.md` §5 — analyst-defined reporting conventions, not measured targets).

## 1. Load the data (Get Data)

1. **Home → Get Data → Text/CSV** → `data/processed/trusted_analysis_table_sample.csv`
   (or **Get Data → Parquet** → `data/processed/trusted_analysis_table.parquet` for the full table).
   Rename the query/table to `Fact_Shipment`.
2. **Get Data → Text/CSV** for each dimension: `dim_hub.csv` → `Dim_Hub`, `dim_route.csv` → `Dim_Route`,
   `dim_vehicle.csv` → `Dim_Vehicle`, `dim_warehouse.csv` → `Dim_Warehouse`, `dim_category.csv` →
   `Dim_Category`, `dim_date.csv` → `Dim_Date`.
3. **Append the UNKNOWN members** (Power Query → Append Queries), otherwise UNKNOWN/Unknown shipments vanish
   from sliced visuals:
   - `Dim_Route` ← append `data/reference/dim_route_unknown_member.csv` (one row, `UNKNOWN`).
   - `Dim_Vehicle` ← append one row: `vehicle_id = UNKNOWN`, `vehicle_type = Unknown`, other columns blank
     (1,543 shipments carry `vehicle_id = UNKNOWN`).
   - `Dim_Category` ← append one row: `category = Unknown`, `base_cost_inr` blank (857 shipments).
4. **Set data types in Power Query** (this is the most common source of wrong cards — do not skip it):
   - `Fact_Shipment[shipment_date]` → Date; `promised_ts_utc` / `actual_ts_utc` → Date/Time (values are
     already UTC — strip the offset, do not re-interpret as IST).
   - `shipment_cost_inr`, `late_hours`, `dwell_origin_h`, `dwell_dest_h`, `dwell_avg_h` → Decimal Number.
   - `on_time`, `cost_valid`, `dwell_origin_valid`, `dwell_dest_valid` → **True/False (logical)**. The CSV
     stores them as text; every DAX measure depends on them being logical.
   - `Dim_Date[date]` → Date.
5. **Add a calculated column** on `Fact_Shipment` (Modeling → New column):
   `Half = IF ( MONTH ( Fact_Shipment[shipment_date] ) <= 6, "H1 2025", "H2 2025" )`.
6. **Optional:** load `data/processed/scan_events_clean.parquet` (Parquet, 1,194,000 rows) as `Fact_Scan_Event`
   for the Data Quality page only. Skip it on a first build — nothing on pages 1–3 needs it.
7. **Load the validation tables** (Text/CSV, **do not relate them** to the model): `outputs/kpi_reports/monthly_kpi.csv`,
   `hub_destination_kpi.csv`, `route_kpi.csv`, `warehouse_kpi.csv`, `category_kpi.csv`, `half_year_kpi.csv`.
   They are disconnected reference tables used only to cross-check DAX results (see §6).

## 2. Build the model (Model view)

Create the relationships exactly as listed in `DAX_Measures.md` §3 (all single-direction, many-to-one, fact → dimension):

| From | To | Active? |
|---|---|---|
| `Fact_Shipment[destination_hub]` | `Dim_Hub[hub_id]` | Yes |
| `Fact_Shipment[origin_hub]` | `Dim_Hub[hub_id]` | **No — inactive** (second role of the same dimension; use `[OTD % (Origin Hub)]` with `USERELATIONSHIP`) |
| `Fact_Shipment[route_id]` | `Dim_Route[route_id]` | Yes |
| `Fact_Shipment[vehicle_id]` | `Dim_Vehicle[vehicle_id]` | Yes |
| `Fact_Shipment[category]` | `Dim_Category[category]` | Yes |
| `Fact_Shipment[warehouse_id]` | `Dim_Warehouse[warehouse_id]` | Yes |
| `Fact_Shipment[shipment_date]` | `Dim_Date[date]` | Yes |
| `Fact_Scan_Event[shipment_id]` → `Fact_Shipment[shipment_id]` (if loaded) | | Yes |
| `Dim_Warehouse[hub_id]` | `Dim_Hub[hub_id]` | Yes |

Then: right-click `Dim_Date` → **Mark as date table** (date column `Dim_Date[date]`). This enables the
`PREVIOUSMONTH` measures. Do **not** add relationships on `Dim_Route[origin_hub]`, `Dim_Route[destination_hub]`
or `Dim_Vehicle[home_hub]` — they are descriptive only and would create ambiguous paths to `Dim_Hub`.

## 3. Add the measures

Copy every measure from `DAX_Measures.md` §4–§5 into the model (Modeling → New measure; keep them in a
`KPI Measures` table or on `Fact_Shipment`). Set the formats stated there: `[OTD %]` Percentage, 2 decimals;
`[Cost per Shipment (INR)]` Currency ₹ (en-IN), 2 decimals; dwell measures Decimal Number, 2 decimals;
`[OTD % MoM Change (pp)]` and `[OTD % Half-Year Change (pp)]` Decimal Number, 2 decimals.

## 4. Build the four pages

General formatting: page size 16:9; title text box at the top of every page with the page name and the line
"Synthetic data (seed 42) — fictional cold-chain distributor, 2025. Not real company data.";
all OTD visuals use `[OTD %]` (never a raw average of a percentage column); all cost visuals use
`[Cost per Shipment (INR)]`; all dwell visuals use `[Avg Destination Dwell (h)]` unless stated otherwise.
Apply the RAG conditional formatting from `DAX_Measures.md` §5 (font colour by the underlying numeric measure).

## 5. Publishing & sharing

1. **Save** as `Logistics_KPI_Performance_Review.pbix` in `powerbi/` (do not commit large data files elsewhere —

## 7. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `[OTD %]` shows ~89% or counts look too high | `on_time` imported as text, so `= TRUE()` never matches and blanks are counted | Power Query: change `on_time` (and the other `*_valid` columns) to True/False logical, reload |
| `[Cost per Shipment (INR)]` is far too low / blank | `shipment_cost_inr` imported as text, or `cost_valid` is text | Same fix for `cost_valid`; check the cost column is Decimal Number |
| Hub visuals show an `UNKNOWN` hub | Canonical hub ids were mapped through the crosswalk as if they were raw spellings | Not a dashboard bug — rebuild `Fact_Shipment` from the supplied cleaned files, don't re-clean in Power Query |
| Route visual drops ~1,500 shipments | `Dim_Route` UNKNOWN row not appended | Append `dim_route_unknown_member.csv` (§1 step 3) and refresh |
| Category visual drops 857 shipments | `Dim_Category` Unknown row not appended | Append the Unknown row (§1 step 3) and refresh |
| `[OTD % MoM Change (pp)]` is blank everywhere | `Dim_Date` not marked as a date table, or the relationship is on `month` text instead of `date` | Mark as date table (§2); relationship must be `Fact_Shipment[shipment_date]` → `Dim_Date[date]` |
| Cards show 76.62% / ₹4,123.31 instead of 76.48% / ₹4,102.68 | The 10,000-row sample CSV is loaded, not the full parquet | Expected — see the sample warning (§0). Load the parquet for exact headline values |
| Monthly trend shows one month only | `Dim_Date[month]` text used as the axis without sorting | Use `month_name` sorted by `month`, or `Dim_Date[date]` with a month hierarchy |
